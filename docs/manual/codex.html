The Three Standard Questions

In fidelity to the system codex, every element, mechanic, module, and store in this reference answers three architectural questions: What It Does (syntax, interaction patterns, user-facing behavior), How It Works (internal execution trace through parser, pagination grid, storage, and DOM stage manager), and Why It Works (software engineering patterns, typographic standards, and durability guarantees).

🎬 Screenplay Elements (Fountain Syntax)

The foundational semantic units of dramatic text parsed by src/fountain.js and formatted on the Courier character grid.

Element Syntax / Pattern Summary
Scene Heading INT. LOCATION - DAY or .HEADING Establishes camera location, lighting condition, and scene numbering.
Action Block Standard prose or !FORCED ACTION Narrative description of visual action, character movement, and sound.
Character Cue NAME, NAME (V.O.), @NAME, NAME ^ Speaker identification cue centered over subsequent dialogue.
Dialogue & Lyrics Spoken text or ~LYRICS LINE Spoken words rendered in a narrow 35-character centered column.
Parenthetical (wryly) immediately under cue Actor direction or vocal instruction subordinate to a character cue.
Transition CUT TO: or > FADE OUT Visual editing instruction formatted flush right.
Centered Text > THE END < Text centered horizontally across the full page width.
Sections & Synopses # Act I / = Synopsis text Outlining structures that organize scenes without printing to paper.
Page Break === on its own line Forces an immediate paper page advance on print and PDF output.
Notes & Boneyard [[Note]] or /* Omitted */ Editorial comments and hidden text omitted from printed pages.

Scene Heading : Slugline Element

🎬 Screenplay Element Column 0 Courier 60ch 
INT. ABANDONED OBSERVATORY - NIGHT #12#
.OUTSIDE THE VAULT DOORS - CONTINUOUS
What It Does

Establishes the setting, camera perspective, time of day, and optional scene number. Must be rendered in pure UPPERCASE preceded and followed by a blank line.

How It Works
  1. Parsing: Fountain.classifyLines() checks for standard prefixes (INT., EXT., EST., INT/EXT., I/E.) or leading forced period (.).
  2. Scene Number Extraction: Trailing #num# tokens are parsed and isolated from the heading text.
  3. Pagination: paginate.js reserves 1 blank line above and below. If fewer than 2 lines remain on the current page, the heading is automatically pushed to the top of the next page to prevent orphans.
Why It Works

Scene headings form the structural skeleton for scene breakdown reports, call sheets, and outline navigation. Preventing orphaned headings ensures scripts look professional during production table reads.

Action : Narrative Prose Block

🎬 Screenplay Element Column 0 Courier 60ch 
Marcus adjusts the brass lens. The gears hum softly.
!HE TURNS TO FACE HER IN TOTAL SILENCE.
What It Does

Describes visual action, character behavior, setting details, and sound effects. Spans the full standard 60-character column width (1.5" left margin, 1.0" right margin).

How It Works
  1. Classification: Any paragraph not meeting the criteria for heading, cue, transition, or metadata is classified as Action.
  2. Forced Action: An initial exclamation mark (!) overrides heuristics, allowing lines in pure uppercase to remain action rather than becoming character cues.
  3. Wrapping: paginate.js breaks action text at word boundaries to fit strictly within 60 Courier monospace columns.
Why It Works

Preserves standard literary prose freedom while guaranteeing that margins never exceed the precise 60-character industry ceiling.

Character Cue : Speaker Identification

🎬 Screenplay Element Column 20 Courier 38ch 
MARCUS (V.O.)
@DR. EVELYN CROSS
ELENA ^
What It Does

Names the character about to speak. Indented to column 20 (3.5" left margin). Supports vocal extensions ((V.O.), (O.S.)), forced prefixes (@), and dual dialogue carets (^).

How It Works
  1. Inference: An uppercase line preceded by a blank line and followed by non-blank text is identified as a Character Cue.
  2. Extensions: Vocal modifiers enclosed in parentheses are preserved alongside the character name.
  3. Dual Dialogue: Ending the cue with a caret (^) marks the speech as simultaneous with the preceding character's dialogue.
Why It Works

Anchors dialogue indexing, character speech metrics, and script breakdown reports without requiring manual indentation.

Dialogue & Lyrics : Spoken Speech

🎬 Screenplay Element Column 10 Courier 35ch 
We have less than three minutes before the seal breaks.
~ Row, row, row your boat...
What It Does

Represents spoken lines of text indented to column 10 (2.5" left margin) with a strict maximum line width of 35 characters. Lines starting with ~ designate lyrics and render in italics.

How It Works
  1. Context Dependency: Non-blank lines immediately following a Character Cue or Parenthetical are categorized as Dialogue.
  2. Formatting: Wrapped at word boundaries within 35 characters. Inline emphasis (*italic*, **bold**, _underline_) is transformed into styled HTML spans.
Why It Works

Tight 35-character wrapping creates the distinctive centered column of dialogue that screenwriters and actors rely on for quick line reading.

Parenthetical : Actor Direction

🎬 Screenplay Element Column 15 Courier 25ch 
(whispering)
(to Evelyn, laughing)
What It Does

Provides brief instructional cues regarding tone, delivery, or action directly subordinate to a character speech, enclosed in parentheses.

How It Works
  1. Detection: A line enclosed in parentheses (...) occurring between a Character Cue and Dialogue or between dialogue lines is recognized as a Parenthetical.
  2. Layout: Indented to column 15 (3.0" left margin) with a max width of 25 characters. Never allowed to stand as the final line of a page.
Why It Works

Provides actors and directors with delivery notes without cluttering dialogue text or distorting speech timing calculations.

Transition : Visual Cut & Fade

🎬 Screenplay Element Column 45 Courier 15ch 
CUT TO:
SMASH CUT TO:
> FADE OUT.
What It Does

Specifies camera transitions, editing cuts, or dissolves, rendered flush right at column 45 (6.0" left margin).

How It Works
  1. Pattern Matching: Uppercase lines ending in TO:, standard keywords (FADE OUT.), or lines beginning with > are classified as Transitions.
  2. Alignment: Lays out flush right against the 60-character right margin.
Why It Works

Adheres strictly to traditional screenplay conventions, signaling pacing shifts cleanly to the reader.

Centered Text : Symmetrical Titles

🎬 Screenplay Element Centered Courier 60ch 
> THE END <
> INTERMISSION <
What It Does

Centers a line of text symmetrically across the full page width, commonly used for act titles or closing tags.

How It Works

Recognizes lines bracketed by > and <, stripping the brackets and calculating leading spaces to center the content mathematically across the 60-column page grid.

Why It Works

Provides an unambiguous notation for centered titles without requiring manual spacebar padding.

Sections & Synopses : Outlining Elements

🎬 Screenplay Element Outline Layer Non-Printing 
# ACT I: THE SUMMONING
## SEQUENCE 1 - THE CRYPT
= Elena discovers the unbroken brass seal.
What It Does

Structural outlining markers that organize your screenplay into acts, sequences, and scene synopses. Never appear on printed pages or PDF exports.

How It Works
  1. Sections (#): Parsed hierarchically by outline.js to generate a navigation tree. Top-level sections automatically serve as chapter titles for YouTube video export.
  2. Synopses (=): Lines beginning with = attach descriptive summary notes to the preceding scene or section.
  3. Print Exclusion: paginate.js completely drops sections and synopses from paper layout.
Why It Works

Writers can embed detailed outlines, beats, and production notes directly into the manuscript without polluting final printed scripts.

Page Break : Forced Sheet Advance

🎬 Screenplay Element Pagination Hook Three Equals 
===
What It Does

Forces an immediate advance to a new paper page in Print, PDF, and Sheets View.

How It Works

A line containing three or more consecutive equal signs (===) signals paginate.js to pad the remaining lines on the current sheet with empty rows and begin a fresh page.

Why It Works

Gives the writer exact control over act breaks and dramatic transitions.

Notes & Boneyard : Editorial Comments

🎬 Screenplay Element Editorial Non-Printing 
[[Check historical accuracy of brass gears]]
/* OMITTED SCENE 14:
Elena's monologue removed for pacing.
*/
What It Does

Allows inline editorial annotations ([[...]]) and large multi-line omitted text blocks (/* ... */) that remain visible in the editor but are excluded from output.

How It Works
  1. Inline Notes: Text bracketed by [[...]] is recognized by fountain.js and styled in muted yellow within the Void and Canvas, but omitted during pagination.
  2. Boneyard: Text enclosed within /* ... */ is stripped completely from the block generation pipeline.
Why It Works

Enables writers to leave notes for co-writers or archive discarded dialogue drafts directly within the file without creating messy separate scratch documents.

⌨️ Typing Engine & Kinetic Modifiers

The keyboard-driven interaction layer that eliminates formatting menus and keeps your hands on the home row.

Tab Element Cycling : Modeless Keyboard Navigation

⌨️ Typing Mechanic src/editing.js Key: Tab
What It Does

Cycles the semantic element type of the current editing line with a single keypress.

How It Works
  1. Editing.tab(text, caret) analyzes the current line's element classification.
  2. If the line is Action, it advances to Character; Character advances to Scene Heading; Scene Heading advances to Transition; Transition cycles back to Action.
  3. Inside dialogue, Tab toggles between Dialogue and Parenthetical. If autocomplete chips are visible, Tab accepts the active suggestion chip.
Why It Works

Eliminates mouse clicks. A single muscle-memory keystroke cycles any line into the desired screenplay format instantly.

Smart Enter State Machine : Predictive Flow

⌨️ Typing Mechanic src/editing.js Key: Enter
What It Does

Anticipates the next logical element type when the writer presses Enter.

How It Works

Pressing Enter on a Character Cue or Parenthetical automatically positions the cursor on the next line formatted as Dialogue. Pressing Enter after Dialogue inserts a blank line and resets the next line to Action.

Why It Works

Matches natural writing rhythms. Speeches flow seamlessly without requiring manual formatting commands between cues, parentheticals, and spoken lines.

Auto-Uppercase Engine : Typing Normalization

⌨️ Typing Mechanic src/editing.js Undoable
What It Does

Automatically transforms scene heading prefixes and transition tags into uppercase as you type, without requiring the Caps Lock key.

How It Works

Editing.autoCase() inspects characters as they are entered. Typing int. automatically capitalizes the token to INT.. Typing cut to: automatically capitalizes the line to CUT TO:. The transformation is committed through applyEdit, ensuring it can be undone with standard Ctrl/Cmd+Z.

Why It Works

Relieves the writer of toggling Caps Lock, preserving flow during rapid drafting.

Autocomplete Suggestion Chips : Context Suggestions

⌨️ Typing Mechanic src/suggest.js Element Bar
What It Does

Presents clickable suggestion chips in the bottom element bar for character names, scene locations, and lighting conditions.

How It Works

Suggest.at(text, caret) scans the active document for known tokens. On a Character line, it displays matching character names. Following a scene hyphen, it suggests lighting terms (DAY, NIGHT). Pressing Tab accepts the first chip.

Why It Works

Ensures naming consistency across 120-page drafts without intrusive popup overlays that obscure nearby text.

Character Name Guessing : Cue Prediction

⌨️ Typing Mechanic src/editing.js Configurable
What It Does

Infers that a short, unpunctuated line following a blank line is intended as a character cue when Enter is pressed.

How It Works

Evaluates the line against known character names in the script. If matched, it automatically uppercases the line, marks it as a Character Cue, and advances the cursor directly into dialogue. Can be disabled in Settings if preferred.

Why It Works

Allows drafting dialogue exchanges rapidly without touching Tab or Caps Lock between speakers.

Focus Mode & Veils : Typewriter Immersion

⌨️ Typing Mechanic src/app/focus.js Ctrl+Shift+F
What It Does

Centers the active cursor line vertically on the screen and dims all surrounding paragraphs behind gradient veils.

How It Works

Toggled via Ctrl/Cmd+Shift+F. focus.js centers the active editing line vertically in the viewport and renders subtle gradient veils over lines above and below the current block.

Why It Works

Reduces ergonomic neck strain during extended writing sessions and curbs the urge to constantly re-read and edit earlier scenes.

Sub-Pixel Syntax Shading : Zero-Lag Color

⌨️ Typing Mechanic src/app/shade.js Wrap-Guarded
What It Does

Provides subtle syntax highlighting behind the cursor without using heavy contenteditable elements.

How It Works

The drafting textarea renders with transparent text over an identically sized background layer (#shade) styled with matching typographic dimensions (line-height: 1.6em). A wrap-drift check disables the layer automatically if text wrapping diverges by even a fraction of a pixel.

Why It Works

Combines the visual clarity of syntax highlighting with the unmatched speed and undo-stack reliability of native textareas.

💾 Storage, Durability & File Bridge

The multi-tier persistence systems ensuring zero data loss and seamless local disk integration.

IndexedDB Scripts Store : Primary Database

💾 Storage plainchant v3 src/store.js
What It Does

Stores all screenplays, metadata, snapshot versions, and file handles in the browser's persistent database.

How It Works

Maintains dedicated object stores (scripts, meta, versions, files) within an IndexedDB database (version 3). Saves execute automatically in the background every 2 seconds.

Why It Works

Bypasses the restrictive 5 MB storage limits of localStorage, allowing writers to store hundreds of scripts safely.

Emergency Unload Buffer : Zero-Loss Reconciler

💾 Storage localStorage pagehide Hook
What It Does

Protects text typed in the 2-second interval before an unexpected tab closure from being lost.

How It Works

On the browser pagehide event, Plainchant writes the active text into localStorage.getItem('plainchant_emergency') synchronously. Upon relaunch, Store.reconcileEmergency() automatically restores any content newer than the database record.

Why It Works

Guarantees that your latest keystrokes survive even if your laptop battery dies or a tab is killed unexpectedly.

Multi-Tab Broadcast Sync : Peer Synchronization

💾 Storage BroadcastChannel Multi-Tab
What It Does

Keeps multiple open Plainchant browser tabs in continuous synchronization.

How It Works

Uses the browser's BroadcastChannel API to broadcast script modifications, creations, and deletions across all open tabs, updating in-memory libraries instantly.

Why It Works

Prevents stale browser tabs from overwriting newer drafts created in other windows.

Snapshot Versions & Pruning : Time-Travel Archive

💾 Storage src/versions.js Logarithmic
What It Does

Automatically preserves historical snapshots of your screenplay at regular intervals, pruning older versions intelligently.

How It Works

Snapshots are created on the first edit of a session and every 10 minutes thereafter. Versions.prune() retains all versions from the past hour, 1 per hour for 24h, 1 per day for 30d, and 1 every 30 days forever. Named versions are never pruned.

Why It Works

Provides complete time-travel version recovery without causing database storage bloat.

Scene Diff & Rollback : Granular Revision

💾 Storage src/compare.js Scene Diff
What It Does

Compares two versions of a script scene-by-scene, allowing you to restore an individual scene from an older draft without rolling back the entire script.

How It Works

Compare.diff() matches scenes by heading across drafts, highlighting modified lines. Clicking Use version's scene replaces only that specific scene in the active script.

Why It Works

Allows writers to safely recover earlier versions of specific scenes without discarding newer work done elsewhere in the draft.

Chromium Live Disk Sync : Local File Bridge

💾 Storage src/filesync.js Chromium API
What It Does

Links scripts directly to real .fountain files on your physical hard drive in Chrome, Edge, and Brave.

How It Works

Uses the File System Access API to bind to local disk files. Every save updates the file on disk. If external tools modify the file, FileSync.decide() detects the change and prompts the writer to resolve any conflicts.

Why It Works

Connects browser-based drafting directly to desktop Git workflows and external backup folders.
