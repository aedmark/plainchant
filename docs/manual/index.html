The Master Philosophy of Plainchant

Plainchant is a lightweight, responsive, local-first screenwriting environment built for writers who would rather write than fuss over format. The writer types plain, unadorned text following the Fountain specification; Plainchant handles structure, typographic alignment, character cues, pagination, and production export automatically.

Book I: Systems Philosophy, Tenets & Origins

1. The Soul of a Distraction-Free Terminal

Modern screenwriting suites have become bloated word processors encumbered by complex proprietary binary file formats, subscription paywalls, intrusive cloud synchronizers, and cluttered toolbars that force the dramatist to manually click dialogue buttons, scene heading rulers, and transition margins.

Plainchant returns screenwriting to its natural elemental state: the rhythm of plain keystrokes. Like Gregorian plainchant—unaccompanied monophonic vocal music stripped of ornamentation—Plainchant strips away all UI noise. You type. As you type, the engine continuously senses the semantic identity of your lines, applies invisible sub-pixel syntax shading behind your cursor, and lays out a live, publication-grade screenplay preview alongside your text.

The Five Core Tenets of Plainchant
  1. Text is the Source of Truth: Scripts are stored and handled as plain Fountain text. There are no proprietary databases, binary blobs, or vendor locks. Everything the application knows about a script—every scene number, dialogue count, speaking character, and estimated runtime—is deterministically derived directly from the text itself.
  2. Never Make the Writer Think About Format: If an action requires the writer to stop drafting, reach for a mouse, and configure formatting, that feature is a design defect. Layout is governed by intelligent keyboard state machines (Tab, smart Enter, auto-casing) or sensible defaults.
  3. Never Lose Words: Durability outranks every feature. A three-tier persistence model—continuous 2-second background autosaves, synchronous unload safety buffers in localStorage, and automatic content-addressed version snapshots—ensures not a single sentence is lost even if a laptop battery dies or a browser tab is killed mid-word.
  4. Lightweight, Zero-Build & Local-First: Plainchant requires zero npm build steps, zero Webpack/Vite bundlers, zero external CDNs, and zero runtime dependencies. It runs directly from disk or over any plain HTTP server, loading self-hosted WOFF2 typefaces and operating completely offline.
  5. Responsive Means Usable: From a 375px mobile handset in an airport to an ultra-wide desktop monitor, the interface dynamically reconfigures its ergonomics: stacked touch viewports with dedicated element selectors on phones, and tiled side-by-side editing panes on desktop workstations.

3. The Zero-Build, Local-First Runtime Model

Software built on complex toolchains decays quickly as npm dependencies rotate and bundlers break. Plainchant is engineered for multi-decade durability. It consists entirely of standard HTML5, CSS3, and modern vanilla JavaScript running natively in evergreen browsers (Firefox and Chromium-based engines). You can clone the repository and launch the app in three seconds: 

# Serve locally using any static web server
python3 -m http.server 8000

# Open in your browser:
# http://127.0.0.1:8000/app.html

When served over HTTP or HTTPS, an integrated Service Worker (sw.js) and Web App Manifest (manifest.webmanifest) automatically cache all assets, turning Plainchant into a standalone, installable Progressive Web App (PWA) that functions indefinitely without network connectivity.

5. The Dual-Layer Architecture: Pure Modules vs. App Scripts

What It Does

Strictly decouples screenwriting business logic from browser DOM side-effects. The engine's core is divided into two distinct tiers: 15 pure UMD modules in src/, and 28 orchestration scripts in src/app/.

How It Works
  1. Pure Layer (src/*.js): Universal Module Definition (UMD) files. They take plain strings or data objects in, and return transformed strings, tokens, or data objects out. They are forbidden from touching window, document, or any browser DOM API.
  2. Stage Layer (src/app/*.js): Classic JavaScript scripts that execute in the browser. They bind DOM event listeners, manage the active textarea caret, paint HTML elements, and coordinate window dialogs.
  3. Load Order Contract: app.html loads all pure domain modules first, followed by the app scripts in deterministic dependency order, concluding with main.js on DOMContentLoaded.
Why It Works

Pure domain modules can be tested headlessly in pure Node.js in milliseconds without JSDOM mocks. Changes to UI appearance or browser event quirks never risk corrupting parsing logic, pagination math, or file synchronization contracts.

7. Global Scope & App Scripts (src/app/)

What It Does

28 classic JavaScript files that power the live interactive UI. They share a single global scope without ES module bundlers, loaded in exact dependency order in app.html.

How It Works
  1. Load Order Determinism: core.js initializes fundamental DOM pointers and rendering pipelines. Subsequent scripts bind specific UI concerns (typing.js, layout.js, shade.js, sheets-ui.js, files-ui.js), culminating in main.js which bootstraps the library on DOMContentLoaded.
  2. Single Program Invariant: Because the scripts share global scope, names cannot collide. Global variables and exported test hooks (e.g. saveScript, setView, openTour) remain top-level function declarations accessible to test runners.
  3. The 500-Line Limit: Enforced by test/structure.test.js: no script in src/app/ is permitted to exceed 500 lines of code. When a feature expands, it must be split by concern into a new dedicated module.
Why It Works

Eliminating ES modules ensures that Plainchant can be opened directly over file:// URLs in modern browsers without triggering CORS module-blocking errors, preserving extreme portability.

8. The Fountain Ingestion & Classification Pipeline

What It Does

Transforms raw script text into an abstract syntax tree of screenplay elements: Scene Headings, Action, Character Cues, Dialogue, Parentheticals, Transitions, Centered Text, Lyrics, Sections, Synopses, Page Breaks, and Notes.

How It Works
  1. Spec-Strict Line Parsing: Fountain.classifyLines(text) evaluates each line using Fountain's standard structural rules. Blank lines serve as structural element boundaries rather than decorative spacers.
  2. Forced Prefix Handling: Explicit markers override heuristics:
    • . forces a Scene Heading (e.g. .THE ROOFTOP)
    • ! forces Action (e.g. !HE WALKS IN SILENCE.)
    • @ forces a Character Cue (e.g. @MCCOY)
    • > forces a Transition (e.g. > SMASH CUT TO:)
    • > ... < forces Centered Text
    • ~ designates Dialogue Lyrics
    • ^ indicates Dual Dialogue (spoken simultaneously with the preceding speech)
  3. Block Segmentation: Fountain.blocks(text) groups classified lines into discrete block objects containing their line range, element kind, and rendered HTML.
Why It Works

Separating line classification from HTML generation allows the editor to use the classification data for syntax shading, autocomplete, and pagination without repeatedly parsing raw strings into heavy DOM nodes.

Book III: The Typing Engine & Ergonomics

9. Sub-Pixel Syntax Shading (shade.js)

What It Does

Provides subtle, non-intrusive syntax coloring directly inside the drafting editor (scene headings in cyan, character cues in emerald, transitions in purple) without using heavy rich-text contenteditable wrappers.

How It Works
  1. The Transparent Overlay: The drafting textarea (#editor) renders its own text transparently (color: transparent; caret-color: var(--caret)).
  2. The Shadow Shading Layer: Directly behind the textarea sits a mirrored div (#shade). shade.js renders syntax-colored text lines into this layer matching Fountain.classifyLines().
  3. Exact Typographic Alignment: copyEditorType() synchronizes font family, font size, letter spacing, word spacing, padding, and an explicit line-height of 1.6em (never unitless) between the two layers.
  4. Wrap-Drift Circuit Breaker: On every render pass, shade.js compares bounding box heights. If browser text wrapping drifts by even a fraction of a pixel, shading automatically turns itself off to prevent visual ghosting.
Why It Works

Preserves native textarea performance. Writers retain 100% native browser undo/redo history, frictionless copy-paste, and IME composition while enjoying rich syntax illumination.

10. Keystroke Heuristics: Tab Cycle & Smart Enter

What It Does

Enables continuous drafting using only two keys: Tab and Enter.

How It Works
  1. Tab Cycling (Editing.tab):
    • On a standalone line: cycles Action → Character → Scene Heading → Transition → Action.
    • Inside a speech: toggles between Dialogue and Parenthetical.
    • When autocomplete chips are visible: accepts the first highlighted suggestion.
  2. Smart Enter (Editing.enter):
    • After a Character Cue or Parenthetical: advances directly into Dialogue on the next line.
    • After Dialogue: produces a standard blank line and resets to Action.
    • After Action: creates a new paragraph. (Shift+Enter inserts a plain line break within the paragraph).
  3. Auto-Uppercase (Editing.autoCase): Detects scene prefixes (INT., EXT.) and transition tags (CUT TO:) and automatically transforms them to uppercase as you type.
  4. Character Name Guessing: Typing a short, unpunctuated name after a blank line and pressing Enter automatically converts the line into an uppercase character cue.
Why It Works

Eliminates the friction of toggling formatting modes. The writer's hands never leave the home row, allowing dramatic thoughts to flow without mechanical interruption.

11. Autocomplete Engine & Suggestion Chips

What It Does

Presents context-aware autocomplete suggestions for character names, scene locations, and lighting tokens directly in the bottom element bar.

How It Works
  1. Dynamic Indexing: Suggest.names() and Suggest.locations() continuously index all unique characters and scene settings established within the current script.
  2. Context Sensitivity:
    • On a Character line: suggests known speaking characters matching the typed prefix.
    • On a Scene Heading after -: suggests standard lighting tokens (DAY, NIGHT, CONTINUOUS, LATER).
    • On a fresh Scene line: suggests recurring locations.
  3. Frictionless Selection: Suggestions appear as clickable chips. Pressing Tab immediately takes the top suggestion. Enter never auto-selects, ensuring natural writing flow is never hijacked.
Why It Works

Maintains character and location spelling consistency across multi-scene screenplays without annoying intrusive popup dropdowns that obscure surrounding lines.

12. Focus Mode & Typewriter Scrolling

What It Does

Locks the active typing line to the vertical center of the screen and dims all surrounding text, creating a pure typewriter writing environment.

How It Works
  1. Activation: Toggled via Ctrl/Cmd+Shift+F or the Focus button in the bottom element bar.
  2. Typewriter Centering: layout.js monitors cursor movements, dynamically scrolling the textarea so the active editing line remains positioned at 50% viewport height.
  3. Opacity Veils: Gradient overlay veils (#veil-top, #veil-bottom) dim all text above and below the active paragraph, keeping only the current thought in sharp focus.
Why It Works

Prevents the writer from constantly looking down at the bottom of the screen during long drafting sessions and minimizes the urge to self-edit prior paragraphs.

Book IV: The Workspace (Void & Canvas)

13. The Dual-Pane Concept: The Void & The Canvas

What It Does

Divides the workspace into two complementary realms: The Void (where raw ideas are typed) and The Canvas (where publication-ready screenplay pages live).

How It Works
  1. The Void (#editor): A focused, distraction-free drafting environment designed for raw velocity.
  2. The Canvas (#render-target): An authentic representation of standard industry screenplay formatting. Can be viewed as a continuous reading stream or as paginated paper sheets.
  3. Caret-Anchored Scroll Sync: As you scroll through the Void, the Canvas smoothly scrolls to keep the corresponding scene in view. On mobile, tapping any paragraph in the Canvas automatically jumps the Void caret directly to that line.
Why It Works

Writers get the raw speed of plain text combined with the immediate reassurance that their dialogue margins, parentheticals, and scene headings conform to Hollywood standards.

14. Block-by-Block Incremental DOM Patching

What It Does

An incremental rendering engine that updates the Canvas preview in under 30 milliseconds, even on massive 160-page feature screenplays.

How It Works
  1. Differential Block Parsing: Fountain.blocks(text) generates a list of blocks. drawPreview() in core.js compares incoming blocks against the previously rendered DOM nodes.
  2. In-Place Mutation: Instead of destroying and rebuilding the entire document, only changed or newly inserted blocks are patched in the DOM. Unmodified scenes remain completely untouched.
  3. Dual-Speed Rendering: Keystroke typing schedules a fast, non-blocking render (render(true)) that updates syntax shading instantly and debounces the Canvas preview to follow immediately after paint.
Why It Works

Eliminates UI lag. Screenwriters can draft feature films without encountering typing delays or stuttering scrollbars.

15. Desktop Multiplexing & Mobile Responsive Stacking

What It Does

Seamlessly adapts the interface across screen sizes from multi-monitor desktop setups to handheld phones.

How It Works
  1. Desktop Mode (≥ 1024px): Provides three selectable layouts toggled via header buttons or keyboard shortcuts:
    • Ctrl/Cmd+Shift+1: Dual Pane (The Void and The Canvas side-by-side).
    • Ctrl/Cmd+Shift+2: The Void alone (maximum typing immersion).
    • Ctrl/Cmd+Shift+3: The Canvas alone (pure reading mode).
  2. Mobile Mode (< 1024px): Switches to single-pane display with a persistent Void | Canvas header toggle. The mobile element bar provides on-screen element switching without dismissing the software keyboard.
  3. Keyboard Clearance: layout.js dynamically calculates the mobile virtual keyboard height, ensuring the active typing line remains at least three lines above the keyboard boundary.
Why It Works

Guarantees a first-class screenwriting experience on any device, whether typing on an iPad on an airplane or revising dialogue on a smartphone.

16. Canvas In-Place Quick Edits

What It Does

Allows writers to fix typos directly in the formatted Canvas preview without switching panes or hunting for the line in the editor.

How It Works
  1. Trigger: Double-clicking on desktop (or pressing and holding for 500ms on touch devices) over any paragraph in the Canvas activates quick editing.
  2. Overlay Bubble: quick-edit.js displays an in-place editing bubble containing the paragraph's raw Fountain text directly over the rendered element.
  3. Atomic Commit: Pressing Enter or clicking outside commits the edit into the main document as a single undoable action (via applyEdit). Pressing Escape cancels the edit cleanly.
Why It Works

Preserves reading flow. Proofreading a screenplay in the Canvas feels natural, allowing quick corrections without disrupting your mental state.

Book V: The Courier Pagination Engine

17. The 60×54/58 Character Grid Specification

What It Does

The mathematical heart of Plainchant's pagination engine (src/paginate.js), adhering strictly to the industry-standard Courier typography grid.

How It Works

Screenplay formatting relies on exact character positions in 10-pitch Courier (10 characters per inch, 6 lines per inch):

Element Left Column Max Width Typographic Rule
Scene Heading Column 0 (1.5" margin) 60 characters UPPERCASE, preceded by 1 blank line, followed by 1 blank line.
Action Column 0 (1.5" margin) 60 characters Standard sentence case, full 60-character line width.
Character Cue Column 20 (3.5" margin) 38 characters UPPERCASE name plus optional extension (e.g. (V.O.)).
Parenthetical Column 15 (3.0" margin) 25 characters Enclosed in parentheses, subordinate to character cue.
Dialogue Column 10 (2.5" margin) 35 characters Spoken speech text, strictly wrapped at 35 characters.
Transition Column 45 (6.0" margin) 15 characters Flush right, UPPERCASE ending in a colon.

On standard US Letter paper, each page accommodates exactly 54 lines. On international A4 paper, each page accommodates 58 lines.

Why It Works

Using an exact integer character grid eliminates font-rendering variations between operating systems, ensuring that 1 page in Plainchant equals exactly 1 minute of screen time.

18. Page Breaks, (MORE) & Orphan Suppression

What It Does

Applies standard Hollywood page-break rules, preventing orphaned headings and cleanly splitting long dialogue blocks across page boundaries.

How It Works
  1. Orphan Suppression: A Scene Heading appearing on the final two lines of a page is automatically moved to the top of the subsequent page.
  2. Dialogue Splitting: If a character's speech crosses a page boundary:
    • The first portion ends with an indented (MORE) line.
    • The top of the next page resumes with the character's name appended with (CONT'D).
  3. Explicit Page Breaks: Typing === in Fountain forces an immediate page break.
Why It Works

Produces publication-quality scripts ready for production table reads without requiring manual adjustments or post-export cleanup.

19. Title Page & Dual Dialogue

What It Does

Lays out professional unnumbered title pages and formats simultaneous speech (Dual Dialogue) side-by-side.

How It Works
  1. Title Page Geometry: Metadata fields at the top of a script (Title:, Credit:, Author:, Draft date:, Contact:) are extracted into an unnumbered title page. Title and authors are centered vertically; contact information is placed in the bottom-left corner.
  2. Dual Dialogue Formatting: When a character cue ends with a caret (SARAH ^), paginate.js renders Sarah's speech directly beside the preceding character's speech in two balanced columns, never splitting them across pages.
Why It Works

Accommodates complex screenplay formatting conventions while keeping the underlying Fountain text completely human-readable.

20. Simulated Sheets View & CSS @page Printing

What It Does

Displays simulated paper sheets with real-time page numbers while writing, and renders clean PDF output via the browser's native print engine.

How It Works
  1. Page View (sheets-ui.js): Toggling Page View in the Canvas header renders individual paper-styled sheets (#sheets) scaled via CSS to fit your viewport.
  2. Print Engine (print.js): Pressing Ctrl/Cmd+P or choosing Export > Print populates #print-root with paginated HTML sheets styled with standard CSS @page declarations, producing razor-sharp vector PDFs directly from Chrome or Firefox.
Why It Works

Eliminates third-party PDF generation dependencies. The browser's native print subsystem handles rendering with zero external bloat.

Book VI: Storage, Durability & File Bridge

21. Multi-Tier IndexedDB v3 Architecture

What It Does

Powers the local script library, storing multiple screenplays, revisions, metadata, and disk file handles in the browser's persistent IndexedDB database (plainchant, version 3).

How It Works
Object Store Key Data Contents
scripts Script UUID Fountain plain text, created timestamp, modified timestamp, word count.
meta "library" Index of active scripts, soft-deleted scripts, and the last open script ID.
versions Composite Key Content-addressed historical snapshots tagged by creation timestamp and commit label.
files Script UUID Chromium FileSystemFileHandle reference for live disk synchronization.
Why It Works

Bypasses the restrictive 5 MB storage ceiling and synchronous main-thread blocking of localStorage, allowing writers to store hundreds of full-length scripts securely in browser storage.

22. The Unload Emergency Buffer Reconciler

What It Does

A fail-safe persistence mechanism that guarantees text typed in the 2-second interval before a sudden tab closure is never lost.

How It Works
  1. The Unload Race: IndexedDB transactions are asynchronous. When a user closes a browser tab, pending IndexedDB writes can be terminated by the browser.
  2. Synchronous Snapshot: Plainchant binds to the pagehide event, instantly writing the full active script text and its ID into localStorage.getItem('plainchant_emergency') synchronously.
  3. Reconciliation on Boot: When Plainchant opens, Store.reconcileEmergency() compares the emergency buffer against the IndexedDB record. If the emergency buffer contains fresher content, it is seamlessly merged into the database.
Why It Works

Guarantees zero data loss under all conditions, fulfilling Tenet 3 (Never Lose Words).

23. Snapshot Versioning & Scene Diffs

What It Does

An automated time-travel version control system built directly into the script library, featuring scene-by-scene comparisons and granular rollbacks.

How It Works
  1. Automated Checkpoints: A revision snapshot is saved on the first modification of a session, and subsequently at 10-minute intervals whenever the text changes.
  2. Logarithmic Thinning (Versions.prune): To prevent database bloat, snapshots are pruned intelligently:
    • All snapshots from the past 1 hour are retained.
    • 1 snapshot per hour for the past 24 hours.
    • 1 snapshot per day for the past 30 days.
    • 1 snapshot every 30 days indefinitely.
    • Named versions created manually by the writer are never deleted.
  3. Scene Comparison (compare.js): The Versions dialog shows a scene-by-scene diff against your current text, allowing you to restore an individual scene from an older version without overwriting the rest of your script.
Why It Works

Gives screenwriters complete creative freedom to experiment, rewrite, and discard drafts with the confidence that any earlier scene can be recovered in seconds.

24. Chromium Live Disk Sync (File System Access API)

What It Does

Links a Plainchant script directly to a real .fountain file on your physical hard drive in Chromium-based browsers, keeping disk and browser storage in continuous synchronization.

How It Works
  1. Linking: Accessed via Library > Open a file... or Export > Sync with a file. Plainchant obtains a FileSystemFileHandle.
  2. Automatic Writing: Every autosave automatically writes the canonical text (\n normalized with a single trailing newline) to the physical file.
  3. Two-Way Dispute Resolution (FileSync.decide): When returning to Plainchant, the engine inspects the file's modification timestamp and content hash:
    • If only the script changed: writes to disk.
    • If only the disk file changed (e.g. edited in VS Code): loads from disk.
    • If both changed: displays a conflict resolution banner allowing the writer to choose which version to keep.
Why It Works

Bridges browser simplicity with native desktop workflows. You can store your scripts in Git repositories or sync folders while drafting in Plainchant.

25. Persistent Storage Leases (safekeeping.js)

What It Does

Protects the browser's IndexedDB database from being cleared during browser disk-cleanup routines.

How It Works
  1. Once a user creates content in Plainchant, safekeeping.js calls navigator.storage.persist().
  2. If granted, the browser promotes storage from "best-effort" to "persistent", preventing automatic eviction under low disk space.
  3. The current lease status is clearly displayed at the bottom of the Library dialog.
Why It Works

Ensures long-term data safety without requiring third-party cloud accounts or server infrastructure.

Book VII: Analytics & Creator Tooling

26. Runtime, Eighths & Word Counts (stats.js)

What It Does

Calculates industry-standard production statistics in real time: total page count, estimated screen time, scene lengths measured in eighths of a page, and word counts.

How It Works
  1. Screen Time: Follows the industry standard rule of thumb: 1 page = 1 minute of screen time, accounting for partial final pages.
  2. Eighths of a Page: Production schedules measure scene lengths in eighths of a page. stats.js calculates scene lengths on the Courier grid, formatting them in standard production notation (e.g. 2 3/8 pgs).
  3. Live Header Counter: The Canvas preview header displays a live page count that updates continuously as you type.
Why It Works

Gives writers and producers immediate production metrics without needing to export the script into separate breakdown software.

27. Dialogue Share & Scene Presence

What It Does

Analyzes character dialogue distribution, speaking counts, and setting balances throughout the screenplay.

How It Works
  1. Character Dialogue Share: Counts the number of speeches and words for each character, calculating their percentage of overall dialogue.
  2. Scene Mix: Breaks down scene settings by interior vs. exterior (INT. vs. EXT.) and time of day (DAY, NIGHT, DUSK, etc.).
  3. Location Index: Aggregates recurring locations, displaying how many scenes and pages take place at each venue.
Why It Works

Helps writers audit character balance, identify pacing issues, and evaluate production budgeting requirements early in the drafting process.

28. The Outline Hierarchy (outline.js)

What It Does

Generates a structured navigational tree of your screenplay based on sections (#), scene headings, and synopses (=).

How It Works
  1. Tree Extraction: Parses top-level acts and sections (# Act I, ## Sequence A), nesting scenes underneath their parent section.
  2. Synopses Attachment: Synopses lines beginning with = are attached directly to their respective scenes in the outline view.
  3. Interactive Jump: Clicking any scene or section in the Outline dialog instantly scrolls both the Void and Canvas directly to that point in the script.
Why It Works

Allows fast structural navigation across 120-page screenplays without manual scrolling.

29. YouTube Chapters & Narration Time

What It Does

Estimates spoken-word read-aloud duration and automatically formats YouTube video chapter timestamps for video essays, podcasts, and documentaries.

How It Works
  1. Spoken Word Calculation: narration.js counts spoken words (dialogue alone, or dialogue plus action) and applies an adjustable reading speed (default: 150 words per minute).
  2. Chapter Generation: Generates formatted YouTube chapter timestamps (e.g. 0:00 Intro, 2:15 The Incident) derived from top-level section headings.
  3. YouTube Policy Verification: Automatically checks compliance with YouTube's chapter requirements (at least 3 chapters, each at least 10 seconds long, starting at 0:00), flagging any issues before you copy the list.
Why It Works

Transforms Plainchant into an indispensable tool for content creators, video essayists, and podcast producers.

Book VIII: Theme Engine & Nostalgia

30. The Three-Theme Token System

What It Does

Provides three complete color themes—Dark (default), Light, and Retro CGA—governed by CSS variables on the root document.

How It Works
  1. CSS Custom Properties: All UI elements derive colors from tokens (--bg-void, --text-strong, --border-void, --btn-bg) declared on :root.
  2. Theme Selection: Switching themes in Settings toggles the data-theme attribute on the <html> element, instantly updating all colors without page reload.
  3. Paper Invariant: The Canvas preview and printed sheets always remain white paper with black text regardless of the active UI theme, preserving typographic fidelity.
Why It Works

Ensures visual consistency while maintaining accessibility and readability across diverse lighting environments.

31. 4.5:1 Contrast Verification

What It Does

Enforces strict WCAG 2.1 AA accessibility standards across all themes and interactive elements.

How It Works

An automated test sweep in test/app.e2e.html (Section 16o) evaluates every button, text element, and icon across all three themes, verifying that text contrast ratios never drop below 4.5:1 and ensuring that every control features an accessible aria label.

Why It Works

Guarantees that Plainchant remains accessible to users with low vision or color vision deficiencies.

32. Retro CGA Theme & The Adventure Game Parser

What It Does

A retro CGA palette mode (cyan, magenta, white, and black) featuring an Easter egg: interactive replies to vintage adventure game commands.

How It Works
  1. CGA Palette: Simulates classic IBM PC Color Graphics Adapter Palette 1 with high-contrast neon accents, crisp borders, and square modal styling.
  2. Adventure Parser (adventure.js): In the Retro theme, typing classic adventure commands (LOOK, INVENTORY, SCORE, XYZZY) on a line of their own and pressing Enter displays a playful in-game response in the notification banner without altering your screenplay text.
Why It Works

Celebrates the computing heritage of text-based interactive storytelling without interfering with professional screenwriting workflows.

Book IX: The Proving Ground (Quality Assurance)

The Proving Ground Philosophy: "Verified Means Observed"

A feature in Plainchant is not considered complete when the code is written; it is complete only when its execution has been observed and validated by automated test suites.

34. Fast Node.js Unit Suite (npm test)

What It Does

A zero-dependency unit test runner executing 339 tests across all pure domain modules in under 1 second.

How It Works

Driven by test/run.js. Tests all 15 pure UMD modules under Node 18+, verifying parser edge cases, Fountain emphasis rules, pagination grid metrics, stats calculations, and file decoding.

Why It Works

Provides instantaneous feedback during development, ensuring algorithms remain mathematically sound before touching browser APIs.

35. Headless Chromium E2E Gauntlet

What It Does

An automated headless browser testing harness (npm run test:browser / bash test/run-headless.sh) executing 327 unit tests and 730 end-to-end integration tests.

How It Works
  1. Launches a real Chromium instance with a fresh, throwaway profile.
  2. Loads test/app.e2e.html, testing real user interactions inside sandboxed iframes: typing keystrokes, modal dialogs, IndexedDB transactions, emergency buffer unloads, and printing simulations.
  3. Completes in approximately 60 seconds with zero external npm dependencies.
Why It Works

Validates complete real-world browser behavior, catching timing issues, storage race conditions, and focus anomalies that unit tests cannot detect.

36. Structural & Manifest Audits (test/structure.test.js)

What It Does

Enforces architectural constraints, preventing architectural drift and unintended dependencies.

How It Works
  1. Verifies that every script in src/app/ is loaded in exact dependency order by app.html.
  2. Enforces that no script in src/app/ exceeds 500 lines of code.
  3. Audits that all font files in fonts/ are accounted for and referenced by src/styles.css.
  4. Verifies that every file used by the app is registered in sw.js's APP_FILES manifest.
  5. Scans filenames to ensure no tracking-related keywords exist that could trigger ad-blocker false positives.
Why It Works

Prevents codebase entropy automatically as the project grows over time.

37. Mutation Testing Protocol

What It Does

Evaluates the effectiveness of the test suite by systematically introducing deliberate bugs into the codebase.

How It Works

A scratch script systematically alters individual lines of code across pure modules and app controllers, running the test suite against each mutation. If the test suite continues to pass, the surviving mutant reveals an untested code path or weak assertion.

Why It Works

Guarantees that test coverage numbers reflect genuine verification rather than hollow execution metrics.

Book X: Contributor Protocol & Appendices

38. The Plainchant Session Protocol

What It Does

The formal procedure governing all development sessions to ensure state continuity and architectural discipline.

How It Works
  1. Start of Session: Read docs/HANDOFF.md (reflecting current state only) and the latest entry in docs/SESSION-LOG.md. Review ROADMAP.md for upcoming milestone IDs.
  2. During Work: Work one roadmap item at a time. Record design rationale in docs/DECISIONS.md. Run the complete test suite before declaring any task complete.
  3. End of Session: Update ROADMAP.md, rewrite docs/HANDOFF.md so it accurately reflects current state, append a session record to docs/SESSION-LOG.md, and log completed milestones in the developer diary (docs/devlog/).
Why It Works

Prevents context loss between development sessions, ensuring smooth continuity across human and AI contributors.

39. Architectural Invariants for Contributors

What It Does

Non-negotiable engineering rules that must be preserved by all pull requests and code modifications.

How It Works
  • No External CDNs or npm Packages: Never add external script tags or npm runtime dependencies. All assets must remain self-contained.
  • Classic Script Tags Only: Do not introduce ES module syntax (import/export) into app controllers, preserving file:// URL compatibility.
  • Pure Modules Must Never Touch the DOM: Code inside src/*.js must remain completely free of window, document, and browser APIs.
  • Never Assign editor.value Directly: All interactive edits must go through applyEdit() to preserve the native browser undo stack.
Why It Works

Safeguards the long-term maintainability, speed, and privacy of the application.

40. Offline PWA & Service Worker Architecture

What It Does

Enables full offline operation and native desktop/mobile installation via Progressive Web App technology.

How It Works
  1. Asset Caching: sw.js maintains an explicit array of core assets (APP_FILES). On installation, all assets are cached locally.
  2. Cache-First Strategy: Requests are served directly from the local cache, guaranteeing instant load times regardless of network availability.
  3. Manifest Configuration: manifest.webmanifest declares application icons, theme colors, and standalone display mode, allowing Plainchant to run in a dedicated app window.
Why It Works

Delivers the responsiveness and reliability of a native desktop application with the zero-install convenience of the web.
